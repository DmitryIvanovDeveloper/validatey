# Процесс анализа данных в системе Validatey

## Обзор системы

Validatey — это система для валидации гипотез стартапов путем анализа данных из различных источников: комментариев Reddit, HackerNews, ProductHunt, опросов пользователей и академических исследований. Система использует поведенческий анализ для оценки предположений проекта.

## Источники данных

### 1. Комментарии из сообществ
- **Reddit**: Поиск по ключевым словам, анализ конкретных постов и субреддитов
- **HackerNews**: Анализ комментариев из разделов top, new, ask, show, jobs
- **LinkedIn**: Комментарии к постам в профессиональных группах

### 2. Опросы пользователей (Founder Validation Pain Survey)
- Анонимные ответы пользователей о болевых точках и поведении
- Структурированные вопросы о готовности платить, частоте проблем и т.д.

### 3. Рынковые данные
- **ProductHunt**: Поиск похожих продуктов через Algolia API
- **Академические исследования**: Анализ научных статей по темам

### 4. Ранние сигналы (Early Signals)
- Пользовательские заметки о наблюдаемых трендах
- Качественные наблюдения из поля

## Процесс сбора данных

### Этап 1: Генерация поисковых запросов
Система автоматически генерирует поисковые запросы на основе гипотезы проекта:

```javascript
const SEARCH_QUERY_PROMPT = `You are a search query expert. Given a startup hypothesis, generate ONE short English search query...

Rules:
- Output ONLY the query string. No quotes, no explanation, no punctuation at the end.
- 3-5 words ONLY.
- Focus on the CORE PROBLEM or BEHAVIOR the hypothesis addresses
- Use plain everyday language that real people use in forum discussions
```

**Примеры запросов:**
- "founders need honest feedback" (для платформы peer-feedback)
- "reciprocal feedback community" (для механики give-to-get)
- "remote team async communication" (для инструментов async видео)

### Этап 2: Сбор комментариев
- **Лимит**: До 10,000 комментариев на проект
- **Источники**: Автоматический поиск по Reddit и HN на основе сгенерированных запросов
- **Хранение**: В базе данных Supabase с таймаутом 60 секунд на загрузку

### Этап 3: Фильтрация и анализ релевантности
Комментарии фильтруются по релевантности к предположениям проекта:
- **Тематические счетчики**: Предварительный подсчет комментариев по ключевым словам для каждого предположения
- **Фильтрация**: Отбор наиболее релевантных комментариев (до 25 на источник)
- **Рейтинг**: Оценка релевантности комментариев к конкретным предположениям

## Поведенческий анализ предположений

### Структура предположения
Каждое предположение анализируется по 4-шаговому алгоритму:

1. **Идентификация аудитории**: Извлечение групп пользователей из гипотезы проекта
2. **Определение актора и поведения**: Кто делает что (ACTOR GROUP + BEHAVIOR)
3. **Проверка покрытия и доказательств**: Соответствие данных предположению
4. **Проверка противоречий**: Анализ на наличие противоречащих данных

### Типы статусов предположений

#### ✅ CONFIRMED (Подтверждено)
- Есть прямые доказательства поведения из комментариев или опросов
- Аудитория представлена в данных
- Поведение явно описано пользователями

**Пример доказательства:**
```
Of 415 comments, ~45 match the topic of this assumption; founders context IS confirmed.
Sample comments show founders explicitly stating they want structured feedback exchange.
Behavioral evidence confirmed through beta testing data.
```

#### 🔍 NEED_MORE (Нужны дополнительные данные)
- Аудитория представлена, но нет доказательств конкретного поведения
- Есть жалобы на проблемы, но не подтверждение решения
- Необходимы дополнительные исследования (интервью, A/B тесты, бета-тестирование)

**Пример доказательства:**
```
Founders context IS confirmed — of 415 comments, ~32 match the topic.
Comments show pain around getting honest feedback, but behavioral evidence that founders
will exchange feedback in structured platform is missing — need user interviews with actual founders.
```

#### ❌ NOT_SUPPORTED (Не поддерживается)
- Данные противоречат предположению
- Поведение пользователей отличается от заявленного
- Прямые доказательства отсутствия востребованности

### Алгоритм оценки

#### Шаг 1: Идентификация аудитории
Из гипотезы проекта извлекаются группы пользователей:
- entrepreneurs, founders, indie hackers, solopreneurs, bootstrappers, startup founders, builders
- investors, customers, users, teachers, developers

#### Шаг 2: Анализ ACTOR GROUP + BEHAVIOR
Для каждого предположения:
- **ACTOR GROUP**: Группа людей (founders, users, investors) — НИКОГДА не абстрактные понятия
- **BEHAVIOR**: Конкретное действие или убеждение

#### Шаг 3: Проверка покрытия данных
```javascript
// Проверка соответствия аудитории
MATCH RULE: if the ACTOR word appears ANYWHERE inside the [audience: ...] label text → MATCH ✓

// Использование тематических счетчиков
"Thematic counts give pre-computed, keyword-based counts of how many comments match each assumption's core topic across ALL collected comments"

// Запрет на частичное цитирование
"Do NOT cite only a subset of sources (e.g. '6 from r/X, r/Y') — cite the thematic count and total"
```

#### Шаг 4: Оценка поведенческих доказательств
**Прямые доказательства поведения:**
- Явные заявления о намерениях
- Описания действий пользователей
- Результаты A/B тестов
- Обратная связь из бета-тестирования

**НЕ являются доказательствами:**
- Жалобы на проблемы (pain points)
- Общие фрустрации
- Описания проблем без действий

## Техническая реализация

### Модель LLM
- **По умолчанию**: llama3.3-70b (ограничение 8192 токена)
- **Альтернатива**: gpt-4-turbo (для больших контекстов)
- **Настраивается**: через переменную ANALYSIS_MODEL

### Лимиты и оптимизации
```javascript
const maxTokens = Math.max(3500, assumptions.length * 250); // ~300 токенов на предположение
const RESEARCH_COMMENTS_LIMIT = 10_000; // Максимум комментариев
const SAMPLE_LIMIT = 25; // Комментариев на источник для LLM
```

### Промпт-инжиниринг
Система использует детально проработанный промпт с:
- Четкими инструкциями по 4-шаговому анализу
- Запретами на распространенные ошибки
- Структурированным выводом в JSON формате
- Правилами использования тематических счетчиков

## Вывод и использование результатов

### Формат вывода
```json
[
  {
    "assumptionId": "exact-id-from-input",
    "status": "confirmed" | "need_more" | "not_supported",
    "evidence": "1-2 предложения объясняющие статус с конкретными данными"
  }
]
```

### Интеграция с UI
- Визуализация в виде donut chart (подтвержденные/нуждающиеся в данных/неподдерживаемые)
- Детальные доказательства для каждого предположения
- Возможность глубокого анализа комментариев

### Качество и валидация
- Автоматическая проверка на противоречия
- Запрет на меж-аудиторные выводы
- Обязательные доказательства для каждого статуса
- Fallback-оценки при ошибках LLM

## Ограничения и рекомендации

### Ограничения
- Анализ основан на публичных данных (Reddit, HN)
- Поведенческий анализ требует прямых доказательств действий
- LLM может ошибаться при сложных предположениях

### Рекомендации по улучшению
- Дополнять анализ пользовательскими интервью
- Проводить A/B тестирование для подтверждения поведения
- Собирать больше данных из целевой аудитории
- Регулярно обновлять поисковые запросы

### Метрики качества
- **Покрытие аудитории**: Процент аудиторий с данными
- **Глубина анализа**: Количество комментариев на предположение
- **Точность выводов**: Соответствие выводов реальному поведению пользователей
